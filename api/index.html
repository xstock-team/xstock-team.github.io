API 总览

约 1266 字大约 4 分钟

xstock 供货 API 采用单入口、命令式风格：所有命令都向同一个地址 /v1 调用，用 cmd 指定命令，请求与响应都使用 jcmd 信封。

  • 查询命令（5 个）：GET，jcmd 字段放在 query 上，不改服务端状态。
  • 写入命令（3 个）：POST，jcmd 放在 JSON 请求体里。
查询  GET  https://api.xstock.example/v1?cmd=get_avail&id=...&stamp=...&data=...
写入  POST https://api.xstock.example/v1
Content-Type: application/json; charset=utf-8

X-Xstock-Api-Key:    <店铺 API Key>
X-Xstock-Timestamp:  <Unix 秒>
X-Xstock-Signature:  <签名>

接入地址

上例中的域名为占位。实际接入地址、API Key 与 Secret 在开户并创建店铺时下发，以门户「店铺详情」页展示的为准。

查询命令（GET）

查询命令把 jcmd 字段放在 query 上，data 为 URL 编码后的 JSON 字符串：

GET /v1?cmd=get_avail&id=shop-a-20261124-0001&stamp=1795000000&data=%7B%22sku_ids%22%3A%5B%22sku_demo_01%22%5D%7D
参数类型必填说明
cmdstring是命令名，区分大小写
idstring是消息标识，1–64 字符
datastring是命令参数的 JSON 字符串，需 URL 编码；无参数时为 %7B%7D（即 {}）
stamplong是Unix 时间戳（秒，UTC），与请求头 X-Xstock-Timestamp 一致

查询签名对参数名升序拼接后的 query 计算，规则见认证与签名。

写入命令（POST）

写入命令用 JSON 请求体承载 jcmd 信封：

{
  "id": "shop-a-20261124-0001",
  "cmd": "req_order",
  "data": {
    "ext_req_id": "shop-a-20261124-0001",
    "items": [{ "sku_id": "sku_demo_01", "qty": "1" }]
  },
  "stamp": 1795000000
}
字段类型必填说明
idstring是消息标识，1–64 字符，用于排障与对账；重试沿用同一个值
cmdstring是命令名，区分大小写，取值为下方命令一览中的 cmd
dataobject是命令参数，无参数时传 {}
stamplong是Unix 时间戳（秒，UTC），与请求头 X-Xstock-Timestamp 一致

响应信封（jcmd）

成功时 code 为 0：

{
  "id": "shop-a-20261124-0001",
  "cmd": "get_quote",
  "code": 0,
  "msg": "",
  "data": { },
  "stamp": 1795000001
}

失败时 code 非 0、data 为 null，msg 说明原因：

{
  "id": "shop-a-20261124-0001",
  "cmd": "get_quote",
  "code": 40201,
  "msg": "账户可用余额不足",
  "data": null,
  "stamp": 1795000001
}
字段说明
id与请求的 id 一致
cmd与请求的 cmd 一致
code整数结果码，0 成功，非 0 失败；分类与重试策略见错误与重试
msg可直接展示给人的说明，不要按文案做程序判断
data业务数据；失败时为 null
stamp平台处理时间戳（Unix 秒）

错误码数值

文中示例错误码（如 40201）只用于说明格式。实际错误码与含义以开户时下发的接入清单为准。

通用数据类型

金额

{ "amt": "10.00", "ccy": "CNY" }
  • amt 为十进制字符串，不要用浮点数解析。
  • 币种由 ccy 标明，账户结算币种之外不自动换汇。

数量

{ "value": "2", "unit": "block" }
  • value 为十进制字符串，整数商品按 1 递增。
  • unit 为销售单位，与商品目录中的单位一致。

时间

统一 UTC、RFC 3339，例如 2026-11-24T13:05:21Z。请按时间比较，不要依赖本地时区字符串。

标识

  • sku_id：商品规格标识，下单与查询都用它。
  • order_no：订单号，平台生成，按不透明字符串处理，不要解析其中含义。
  • quote_id：报价标识，短时有效。
  • case_no：售后工单号。

分页

列表类动作使用 page（从 1 开始）与 page_size（1–100，默认 20）：

{ "page": 1, "page_size": 50 }

响应含 page、page_size、total 与 has_more。翻页期间数据可能变化，不要用翻页结果判断商品被删除，下架以目录返回的 status 为准。

权限

权限按店铺授予，调用未授权命令返回非 0 的 code（msg 中提示无权限）。

限流

  • 默认每个店铺 60 次/分钟，超出返回 HTTP 429，响应体 code 非 0。
  • 响应头 X-RateLimit-Limit、X-RateLimit-Remaining、Retry-After 可辅助退避。
  • 限流不影响幂等语义：被拒绝的请求不产生业务结果。

版本

  • 当前协议版本为 1.0，通过请求头 X-Xstock-Schema 声明；不传时按最新兼容版本处理。
  • 新增可选字段向后兼容，可忽略未知字段。
  • 改变金额、数量含义或状态枚举时升主版本，并提前在门户公告。
  • 声明的版本与平台不兼容时返回非 0 的 code，不会静默按旧版处理。

排障建议

  1. 保留每次请求的 id、HTTP 状态码、响应体与时间。
  2. 失败先看 code，再看 msg。
  3. 涉及订单的争议，提供 order_no 或 ext_req_id，比截图更快定位。
