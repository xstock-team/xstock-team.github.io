与独角数卡对接

约 1408 字大约 5 分钟

独角数卡（dujiao-next）作为下游商城接入 xstock 时，按它自己的「上游对接」协议工作：连接里填根地址与 Key/Secret，后台通过 ping、products、orders 等接口采购。xstock 的适配层负责把它翻译成平台标准命令，你不需要为独角数卡单独改代码，按它的后台表单填即可。

版本说明

本文依据 dujiao-next v1.6.1 的对接协议整理。适配层仍在联调中，字段以双方实际跑通为准。

连接配置

在独角数卡后台「对接管理 → 连接管理」新建连接：

表单填什么
名称自定义，例如「xstock」
根地址xstock 下发的接入地址（适配层会拼上协议路径）
API Key / Secret门户「店铺详情」里的店铺凭据
协议dujiao-next
回调地址你商城接收回调的公网地址
重试/加价/汇率按你的运营设置

保存后点「测试连接」，即触发一次连通性检测。

独角数卡调用xstock 对应说明

GET /categoriesget_categories分类目录（含层级与商品数）

标识对齐

独角数卡的商品、SKU、订单字段都是自增 INTEGER，因此 xstock 对外统一返回数字 ID，同时附带一个稳定的可读编码：

独角数卡xstock说明
category.id（int）category_id（int64）根分类 parent_id=0
category.slugguid独角本地 slug 与 xstock guid 不同命名空间；映射用数字 ID 或 guid
category.iconthumb分类图片地址（URL 字符串）
product.id（int）goods_id（int64）直接写入 upstream_product_id
product.slugguid商品 GUID 字符串
sku.id（int）sku_id（int64）直接写入 upstream_sku_id
sku.sku_codesku_code单规格为 DEFAULT；只在同一商品内唯一
（跨商品标识）skus[].guidSKU 的全局字符串标识，跨商品唯一，适合持久映射
order_id（int）order_id（int64）创建、查询、取消、回调使用同一个数字
order_noorder_no业务单号字符串，两条链路都保留

数字 ID 是平台下发的协议别名：不复用、不改绑，取值在 JS 安全整数范围内。平台内部的 GUID 主键不对外暴露。

状态映射

xstock status独角数卡处理

签名与协议差异

项独角数卡xstock
路径/api/v1/upstream/*/dist/api/v1/{cmd}
认证头Dujiao-Next-*X-Xstock-*
签名串METHOD\nPATH\nTIMESTAMP\nMD5(BODY)timestamp\ncmd\nSHA256(body 或 query)
响应{ok, ...}jcmd 信封（code=0 成功）

这些差异由 xstock 侧的独角数卡适配层转换，商城端看到的始终是它熟悉的协议。

联调顺序

  1. 门户创建店铺，拿 Key/Secret，配好回调地址。
  2. 独角数卡后台建连接，点「测试连接」应返回成功与余额。
  3. 先拉分类目录，再拉商品清单，建立映射并启用。
  4. 下一笔小额测试单，确认扣款、交付与回调。
  5. 走一遍取消与售后，确认状态回传正确。

排错

现象先查
测试连接失败（401）Key/Secret 是否是当前店铺、时间偏差是否超 300 秒
商品拉不到店铺是否开通 catalog.read、商品是否 is_active
下单返回余额不足门户余额是否够冻结成交金额
回调没到回调地址是否通过校验、是否 5 秒内返回 2xx
状态没更新是否按 event_id 幂等处理、是否按 occurred_at 合并
