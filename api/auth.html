认证与签名

约 981 字大约 3 分钟

凭据

每个店铺有一对凭据，在门户「店铺详情」中生成与轮换：

凭据用途存放位置
API Key标识调用方身份，随请求头发送可在服务端配置中
API Secret计算请求签名，不随请求发送只放服务端密钥配置，禁止进前端

一个店铺同一时间只有一个有效 Secret；轮换时新密钥先生效、旧密钥在宽限期内仍可用，到期自动失效。

请求头

头必填示例说明
X-Xstock-Api-Key是xs_live_2f7c...店铺 API Key
X-Xstock-Timestamp是1795000000当前 Unix 时间戳（秒），与平台时间偏差不得超过 300 秒
X-Xstock-Signature是9f2c1d...小写十六进制 HMAC-SHA256
Content-Type仅 POSTapplication/json; charset=utf-8写入命令固定，GET 查询不需要

签名算法

两种请求形态的签名串不同。

写入命令（POST，jcmd 在请求体）

body_digest = SHA256(raw_request_body) 的十六进制小写
string_to_sign = timestamp + "\n" + cmd + "\n" + body_digest
signature = HMAC_SHA256(secret, string_to_sign) 的十六进制小写

查询命令（GET，jcmd 在 query）

query_digest = SHA256(canonical_query) 的十六进制小写
string_to_sign = timestamp + "\n" + cmd + "\n" + query_digest
signature = HMAC_SHA256(secret, string_to_sign) 的十六进制小写

canonical_query 的生成规则：

  1. 取 query 中的 cmd、id、data、stamp 四个参数（不含签名相关头）。
  2. 按参数名 ASCII 升序排列。
  3. 键与值都做 RFC 3986 百分号编码（空格编码为 %20，不要用 +）。
  4. 用 & 连接成 cmd=...&data=...&id=...&stamp=...。

要点：

  • POST 的 raw_request_body 必须是实际发送的原始字节，不要先解析再重新序列化（字段顺序与空白都会改变摘要）。
  • GET 的 data 也要按第 2–4 步重新拼接后计算，不要直接用浏览器或 HTTP 库拼出来的原始 query 字符串。
  • cmd 取自请求体或 query 中的 cmd，两者保持一致。
  • timestamp 与请求头中的值完全相同。
  • 比较签名时使用常量时间比较。

示例

curl（GET 查询）

TS=$(date +%s)
DATA='{"sku_ids":["sku_demo_01"]}'
QUERY="cmd=get_avail&data=$(printf '%s' "$DATA" | jq -sRr @uri | sed 's/%3A/:/g')&id=demo-1&stamp=$TS"
DIGEST=$(printf '%s' "$QUERY" | openssl dgst -sha256 -hex | sed 's/^.* //')
SIG=$(printf '%s\n%s\n%s' "$TS" "get_avail" "$DIGEST" | openssl dgst -sha256 -hmac "$XS_SECRET" -hex | sed 's/^.* //')

curl -sS "https://api.xstock.example/v1?$QUERY" \
  -H "X-Xstock-Api-Key: $XS_KEY" \
  -H "X-Xstock-Timestamp: $TS" \
  -H "X-Xstock-Signature: $SIG"

curl（POST 写入）

BODY='{"id":"demo-2","cmd":"req_order","data":{"ext_req_id":"demo-0001","items":[{"sku_id":"sku_demo_01","qty":"1"}]},"stamp":1795000000}'
TS=$(date +%s)
DIGEST=$(printf '%s' "$BODY" | openssl dgst -sha256 -hex | sed 's/^.* //')
SIG=$(printf '%s\n%s\n%s' "$TS" "req_order" "$DIGEST" | openssl dgst -sha256 -hmac "$XS_SECRET" -hex | sed 's/^.* //')

curl -sS https://api.xstock.example/v1 \
  -H 'Content-Type: application/json; charset=utf-8' \
  -H "X-Xstock-Api-Key: $XS_KEY" \
  -H "X-Xstock-Timestamp: $TS" \
  -H "X-Xstock-Signature: $SIG" \
  --data-binary "$BODY"

Node.js（GET 查询）

import { createHash, createHmac } from 'node:crypto'

function signQuery({ secret, timestamp, cmd, query }) {
  const digest = createHash('sha256').update(query).digest('hex')
  return createHmac('sha256', secret).update(`${timestamp}\n${cmd}\n${digest}`).digest('hex')
}

const timestamp = Math.floor(Date.now() / 1000).toString()
const query = new URLSearchParams({
  cmd: 'get_avail',
  data: JSON.stringify({ sku_ids: ['sku_demo_01'] }),
  id: 'demo-1',
  stamp: timestamp,
}).toString()

const res = await fetch(`https://api.xstock.example/v1?${query}`, {
  headers: {
    'X-Xstock-Api-Key': process.env.XS_KEY,
    'X-Xstock-Timestamp': timestamp,
    'X-Xstock-Signature': signQuery({ secret: process.env.XS_SECRET, timestamp, cmd: 'get_avail', query }),
  },
})

C#（POST 写入）

using System.Security.Cryptography;
using System.Text;

static string Sign(string secret, string timestamp, string cmd, string rawBody)
{
    var bodyDigest = Convert.ToHexString(SHA256.HashData(Encoding.UTF8.GetBytes(rawBody))).ToLowerInvariant();
    var stringToSign = $"{timestamp}\n{cmd}\n{bodyDigest}";
    using var hmac = new HMACSHA256(Encoding.UTF8.GetBytes(secret));
    return Convert.ToHexString(hmac.ComputeHash(Encoding.UTF8.GetBytes(stringToSign))).ToLowerInvariant();
}

认证失败

HTTPcode原因处理
4011002缺少认证头检查请求头是否被网关剥离
4011002时间戳超时校准系统时间，用 NTP 同步
4011002签名不匹配用原始请求体重算摘要
4011002密钥已撤销在门户轮换后更新配置
4031003店铺无该命令权限在门户勾选权限

安全建议

  • Secret 只存服务端，使用环境变量或密钥管理服务，不写进仓库。
  • 为回调地址开启 HTTPS，并在接收端校验签名。
  • 开启 IP 白名单可显著降低密钥泄露后的风险。
  • 定期轮换密钥；轮换期间保留短时双密钥过渡，避免切流失败。
