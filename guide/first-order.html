第一个订单

约 850 字大约 3 分钟

用一个最小例子走完整链路。假设你已经拿到 API Key 与 Secret，商品 SKU 为 sku_demo_01，数量 1。

调用顺序

get_catalog   →  找到 SKU
get_avail     →  确认可售
get_quote     →  拿到报价（可选但推荐）
req_order → 下单，余额冻结
   ↓ 异步
order.fulfilled 回调（或 get_order 轮询）
   ↓
get_dlv       →  取交付物

1. 拉取商品目录

GET /v1?cmd=get_catalog&id=demo-catalog-1&stamp=1795000000&data=%7B%22page%22%3A1%2C%22page_size%22%3A20%7D HTTP/1.1
Host: api.xstock.example
X-Xstock-Api-Key: xs_live_xxxxxxxx
X-Xstock-Timestamp: 1795000000
X-Xstock-Signature: 9f2c...

返回的 data.items 中每个条目含 sku_id、sku_code、标题、单位、起订量、基础供货价与交付类型。

2. 确认可售

GET /v1?cmd=get_avail&id=demo-avail-1&stamp=1795000000&data=%7B%22sku_ids%22%3A%5B%22sku_demo_01%22%5D%7D HTTP/1.1
Host: api.xstock.example
X-Xstock-Api-Key: xs_live_xxxxxxxx
X-Xstock-Timestamp: 1795000000
X-Xstock-Signature: 9f2c...

available_qty 为快照值，仅用于展示与判断；下单是否成功以接单结果为准，它不锁定库存。

3. 取报价

GET /v1?cmd=get_quote&id=demo-quote-1&stamp=1795000000&data=%7B%22items%22%3A%5B%7B%22sku_id%22%3A%22sku_demo_01%22%2C%22qty%22%3A%221%22%7D%5D%7D HTTP/1.1
Host: api.xstock.example
X-Xstock-Api-Key: xs_live_xxxxxxxx
X-Xstock-Timestamp: 1795000000
X-Xstock-Signature: 9f2c...

返回 quote_id 与 expires_at。在有效期内用该 quote_id 下单，成交金额按报价冻结；报价过期需重新获取。

4. 下单

{
  "id": "demo-order-1",
  "cmd": "req_order",
  "data": {
    "ext_req_id": "shop-a-20261124-0001",
    "ext_order_ref": "202611240001",
    "quote_id": "q_xxxxxxxx",
    "items": [{"sku_id": "sku_demo_01", "qty": "1"}]
  },
  "stamp": 1795000000
}

ext_req_id 是幂等键，必须由你的系统稳定生成：同一笔业务重复提交要用同一个值，新业务必须用新值。

成功返回：

{
  "id": "demo-order-1",
  "cmd": "req_order",
  "code": 0,
  "msg": "",
  "data": {
    "order_no": "XS20261124000123",
    "accept_state": "accepted",
    "fund_state": "held",
    "total": {"amt": "10.00", "ccy": "CNY"},
    "created_at": "2026-11-24T13:05:21Z",
    "lines": [
      {"line_no": 1, "sku_id": "sku_demo_01", "qty": {"value": "1", "unit": "block"}, "net_amt": {"amt": "10.00", "ccy": "CNY"}}
    ]
  },
  "stamp": 1795000001
}

此时余额已冻结、尚未扣款。重复提交同一个 ext_req_id 会返回同一订单号和相同金额（code=0），不会重复扣款。

5. 等待交付

交付是异步的：整单配齐后平台一次性交付并扣款，同时投递 order.fulfilled 事件。

接收回调（推荐）：

{
  "event_id": "evt_01J...",
  "event_type": "order.fulfilled",
  "occurred_at": "2026-11-24T13:05:48Z",
  "data": {
    "order_no": "XS20261124000123",
    "fulfill_state": "full",
    "fund_state": "captured",
    "total": {"amt": "10.00", "ccy": "CNY"}
  }
}

或主动轮询：

GET /v1?cmd=get_order&id=demo-query-1&stamp=1795000000&data=%7B%22order_no%22%3A%22XS20261124000123%22%7D HTTP/1.1
Host: api.xstock.example
X-Xstock-Api-Key: xs_live_xxxxxxxx
X-Xstock-Timestamp: 1795000000
X-Xstock-Signature: 9f2c...

6. 领取交付物

GET /v1?cmd=get_dlv&id=demo-dlv-1&stamp=1795000000&data=%7B%22order_no%22%3A%22XS20261124000123%22%7D HTTP/1.1
Host: api.xstock.example
X-Xstock-Api-Key: xs_live_xxxxxxxx
X-Xstock-Timestamp: 1795000000
X-Xstock-Signature: 9f2c...

返回每条订单行的交付物清单。交付物可能是账号密码组合、卡密、文件或下载链接，按 kind 区分；同一份交付物重复领取不会重复扣款，但每次领取都会记录访问审计。

保存好交付物

交付物是你向消费者履约的凭据。建议在领取后立即落库保存，不要只依赖实时接口。若需要事后核对，可通过订单查询确认交付状态。

失败时怎么判断

返回含义你的处理
1xxx / 2xxx明确拒绝，如余额不足、商品停售不要重试，修正后重新下单
3002同一 ext_req_id 内容不一致检查请求体，确属新业务请换新键
4xxx暂时失败退避重试（同键同内容）
9xxx结果不确定不要重试下单，用 get_order 或 ext_req_id 查询确认

分类细节见错误与重试。
