API 总览

约 2023 字大约 7 分钟

v1 草案

本组文档描述的是 v1 接入协约草案：接口地址、签名细节与错误码在正式接入清单下发前可能调整。已开通联调的分销商请以门户「接入清单」与沙箱实际返回为准；发现不一致请提交工单。

xstock 分销商侧 API 按命令命名空间组织：命令写在路径里，基地址统一为 /dist/api/v1。

  • 查询命令（5 个，含连通性 ping）：GET /dist/api/v1/{cmd}，不使用 jcmd 信封，data 里的字段直接拼成 query。
  • 写入命令（5 个，含只读的 get_avail、get_quote）：POST /dist/api/v1/{cmd}，请求体用 jcmd 信封。
查询  GET  https://api.xstock.example/dist/api/v1/get_avail?sku_ids=sku_a,sku_b
写入  POST https://api.xstock.example/dist/api/v1/post_order
Content-Type: application/json; charset=utf-8

X-Xstock-Api-Key:    <店铺 API Key>
X-Xstock-Timestamp:  <Unix 秒>
X-Xstock-Signature:  <签名>

接入地址

上例中的域名为占位。实际接入地址、API Key 与 Secret 在开户并创建店铺时下发，以门户「店铺详情」页展示的为准；路径前缀 /dist/api/v1 固定不变。

与独角数卡对接

如果下游是独角数卡（dujiao-next），接口与字段映射见与独角数卡对接，适配层会完成协议转换。

规格文件

  • 下载 OpenAPI 3.1 规格（在新窗口打开）（1.0.0-draft）

规格与页面上的交互结构由同一份 schema 数据生成，命令清单、字段结构不会两处走样。命令即路径，OpenAPI 里每个命令一个 path，查询命令是 get、写入命令是 post。

关于试调

在线试调需要沙箱环境与真实签名，当前未开放。联调阶段请用门户下发的测试店铺凭据，在本地按认证与签名实现。

查询命令（GET）

查询命令不用信封：把 data 里的字段逐个拼到 query 上，字段名保持原样。

GET /dist/api/v1/get_goods?page=1&page_size=20
  • 数组：如有数组参数，用半角逗号 , 连接，例如 ids=1,2,3。
  • 布尔：true / false。
  • 数字与金额：按接口文档给出的类型传字符串，不要加千分位。
  • 空参数：data 里没有字段的命令（如 ping）直接请求路径，不带 ?。
  • 字段名、大小写与接口页一致；未识别的字段会被忽略，必填缺失返回 1001。

查询签名对按字段名升序拼接后的 query 计算，规则见认证与签名。

写入命令（POST）

写入命令路径同样带命令名，请求体是 jcmd 信封：

{
  "id": "shop-a-20261124-0001",
  "cmd": "post_order",
  "data": {
    "req_id": "shop-a-20261124-0001",
    "items": [{ "sku_id": 1001, "qty": "1" }]
  },
  "stamp": 1795000000
}
字段类型必填说明
idstring是消息标识，1–64 字符，用于排障与对账；重试沿用同一个值
cmdstring是命令名，须与路径中的命令一致
dataobject是命令参数，无参数时传 {}
stamplong是Unix 时间戳（秒，UTC），与请求头 X-Xstock-Timestamp 一致

响应信封（jcmd）

成功时 code 为 0：

{
  "id": "shop-a-20261124-0001",
  "cmd": "get_quote",
  "code": 0,
  "msg": "",
  "data": { },
  "stamp": 1795000001
}

失败时 code 非 0、data 为 null，msg 说明原因：

{
  "id": "shop-a-20261124-0001",
  "cmd": "get_quote",
  "code": 40201,
  "msg": "账户可用余额不足",
  "data": null,
  "stamp": 1795000001
}
字段说明
id与请求的 id 一致
cmd与请求的 cmd 一致
code整数结果码，0 成功，非 0 失败；分类与重试策略见错误与重试
msg可直接展示给人的说明，不要按文案做程序判断
data业务数据；失败时为 null
stamp平台处理时间戳（Unix 秒）

错误码数值

文中示例错误码（如 40201）只用于说明格式。实际错误码与含义以开户时下发的接入清单为准。

通用数据类型

多语言文本

名称、标题、简介这类会展示给终端用户的字段，统一是语言标签到文本的映射，不是单一字符串：

{ "zh-CN": "流媒体", "en": "Streaming" }
  • 键为 BCP-47 语言标签（如 zh-CN、en、ja），值与当前发布版本一致。
  • 响应里有两级 default_locale：响应级表示站点整体回退语言；商品条目内还有一个，表示该商品自己的回退语言（不同商品可用语言可能不同）。
  • 只包含已发布的语言；未翻译的语言不出现，客户端自行回退到 default_locale 或自己的首选语言。
  • 该字段只读，改语言内容需在门户操作，API 不提供写接口。

金额与多币种价格

单个金额：

{ "amt": "10.00", "ccy": "CNY" }

商品与报价里的价格是多币种数组，一次给出所有可售币种：

"prices": [
  { "amt": "1.00", "ccy": "USD" },
  { "amt": "6.66", "ccy": "CNY" },
  { "amt": "1.10", "ccy": "USDT" }
]
  • amt 为十进制字符串，不要用浮点数解析。
  • default_ccy 有三级：响应级、商品条目、SKU 条目；prices 中一定包含对应层级的默认币种，展示时优先用它，用户切换币种再按 ccy 取。
  • 数组顺序不保证，按 ccy 查找，不要按下标取。
  • 币种之间不自动换汇，各币种价格由平台独立定价。

数量

{ "value": "2", "per": 1 }
  • value 为十进制字符串，整数商品按 1 递增。
  • per 为购买步长（数字），通常为 1；与商品/ SKU 上的 per 一致。

时间

统一 UTC、RFC 3339，例如 2026-11-24T13:05:21Z。请按时间比较，不要依赖本地时区字符串。

标识

对外标识分数字 ID与GUID 字符串两类，二者指向同一对象：

对象数字 ID可读编码说明
分类category_idguid根分类 parent_id 为 0
商品goods_idguid商品清单返回
SKUsku_idsku_code单规格 sku_code 为 DEFAULT
订单order_idorder_no查单/取消/售后可用 order_id 或 order_no
报价—quote_id下单时用于统一单价
售后—ticket_no工单号
  • 数字 ID 是对下游稳定的协议别名：一旦下发就不再改绑、不复用；取值范围 1–9007199254740991（JS 安全整数），按整数解析，不要当字符串拼接。
  • 平台内部另有 GUID 主键，不对外暴露；下游只需要数字 ID 或可读编码即可完成映射。
  • order_no、quote_id、ticket_no 是业务单号，按不透明字符串处理，不要解析其中含义。

分页

列表类动作使用 page（从 1 开始）与 page_size（1–100，默认 20）：

{ "page": 1, "page_size": 50 }

响应含 page、page_size、total 与 has_more。翻页期间数据可能变化，不要用翻页结果判断商品被删除，下架以目录返回的 status 为准。

权限

权限按店铺授予，调用未授权命令返回非 0 的 code（msg 中提示无权限）。

限流

  • 默认每个店铺 60 次/分钟，超出返回 HTTP 429，响应体 code 非 0。
  • 响应头 X-RateLimit-Limit、X-RateLimit-Remaining、Retry-After 可辅助退避。
  • 限流不影响幂等语义：被拒绝的请求不产生业务结果。

版本

  • 当前协议版本为 1.0，通过请求头 X-Xstock-Schema 声明；不传时按最新兼容版本处理。
  • 新增可选字段向后兼容，可忽略未知字段。
  • 改变金额、数量含义或状态枚举时升主版本，并提前在门户公告。
  • 声明的版本与平台不兼容时返回非 0 的 code，不会静默按旧版处理。

排障建议

  1. 保留每次请求的 id、HTTP 状态码、响应体与时间。
  2. 失败先看 code，再看 msg。
  3. 涉及订单的争议，提供 order_no 或 trace_id，比截图更快定位。
