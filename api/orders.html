下单 accept_sales_order

约 749 字大约 3 分钟

提交一笔销售订单。受理即冻结对应余额，整单配齐后交付并扣款。

  • 权限：order.create
  • 幂等：按 ext_req_id（店铺内唯一）

请求

{
  "action": "accept_sales_order",
  "schema_ver": "1.0",
  "req_id": "shop-a-20261124-ord-001",
  "data": {
    "ext_req_id": "shop-a-20261124-0001",
    "ext_order_ref": "202611240001",
    "quote_id": "q_8f21c0",
    "items": [
      { "sku_id": "sku_demo_01", "qty": "2", "input": {} }
    ],
    "remark": null
  }
}
字段类型必填说明
ext_req_idstring是幂等键，店铺内唯一，1–64 字符，建议用业务单号生成，不要用随机数
ext_order_refstring否你商城里的订单号，便于对账与客服定位
quote_idstring否报价标识；带上则按该报价金额成交
itemsarray是订单行，1–20 行
items[].sku_idstring是商品标识
items[].qtystring是数量，满足最小/最大/步长
items[].inputobject否需要填写参数的商品（如自定义链接），按目录规格传入
remarkstring否备注，不放敏感信息

{
  "req_id": "shop-a-20261124-ord-001",
  "corr_id": "c_7f3a94",
  "schema_ver": "1.0",
  "code": "OK",

状态字段

字段取值含义
accept_stateaccepted / rejected是否受理
fulfill_statenone / full是否已整单交付
fund_stateheld / captured / released / refunded资金状态：冻结 / 已扣 / 已释放 / 已退
after_sale_statenone / open / resolving / resolved售后状态（查单时返回）

被拒时 accept_state=rejected，code 为 PERMANENT 并带具体 sub_code，不会冻结资金。

幂等语义

场景结果
同 ext_req_id，请求内容相同返回原订单，code=DUPLICATE，不重复冻结
同 ext_req_id，内容不同CONFLICT，不创建新订单，不冻结
新 ext_req_id新订单

幂等键不要复用

不要把「当前时间 + 商品」拼成幂等键，也不要在重试时重新生成。一次业务请求对应一个固定值；确需重新下单（例如前单已取消）时，使用新键并在你的系统里关联原单。

资金与交付

  • 受理时冻结 total；余额不足返回 INSUFFICIENT_BALANCE。
  • 整单配齐后一次性交付并扣款，不支持分批交付、不分次扣款。
  • 未交付前取消，释放冻结（解冻，不是退款）。
  • 已交付后不支持取消，质量问题走售后。

超时与不确定

若请求超时或网络中断：

  1. 不要换新 ext_req_id 重发。
  2. 用 get_sales_order 按 ext_req_id 查询。
  3. 查到订单按状态继续；确认无单后再用原键重试一次。

返回 UNKNOWN 时同理，先查证。

错误

sub_code场景处理
INSUFFICIENT_BALANCE可用余额不足充值或减少数量
QUOTE_EXPIRED报价过期重新报价
QUOTE_MISMATCH与报价内容不一致按报价内容下单
SKU_SUSPENDED商品暂停销售更新商城展示
QTY_INVALID数量不合规按目录限制调整
DUPLICATE（code）重复提交直接使用返回的订单号
CONFLICT（code）幂等键冲突检查业务单号生成逻辑
