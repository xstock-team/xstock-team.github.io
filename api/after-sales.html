售后 open_after_sales_case

约 659 字大约 2 分钟

对已交付订单提交售后工单，由平台核实处理。适用于交付内容无效、数量不足或与描述不符。

  • 权限：after_sales.write
  • 幂等：按 req_id，同号不重复建单
  • 前置条件：订单 fulfill_state=full

请求

{
  "action": "open_after_sales_case",
  "schema_ver": "1.0",
  "req_id": "shop-a-20261124-as-001",
  "data": {
    "order_no": "XS20261124000123",
    "line_no": 1,
    "kind": "invalid",
    "qty": "1",
    "description": "1 份账号无法登录，提示密码错误，已尝试重置仍失败",
    "evidence": [
      { "kind": "text", "content": "错误提示：账号或密码不正确" },
      { "kind": "link", "url": "https://shop-a.example/case/20261124000123-1.png" }
    ]
  }
}
字段类型必填说明
order_nostring是订单号
line_noint是订单行号
kindstring是invalid 无效 / shortage 数量不足 / mismatch 与描述不符 / other 其他
qtystring是涉及数量，不超过该行已交付量
descriptionstring是问题描述，建议含操作步骤与提示原文
evidencearray否证据：文本或链接，最多 10 条

响应

{
  "req_id": "shop-a-20261124-as-001",
  "corr_id": "c_7f3a98",
  "schema_ver": "1.0",
  "code": "OK",
  "message": "",
  "data": {
    "case_no": "AS202611240007",
    "state": "open",
    "created_at": "2026-11-24T13:20:00Z"
  }
}
state含义
open已受理，待核实
resolving核实中，可能需要补充材料
resolved已处理完成
rejected不成立或证据不足

进度会通过 order.after_sales.updated 事件推送，也可在门户查看。

处理与退款

  • 核实成立后，按核定金额退回账户余额，并生成退款流水。
  • 退款金额以实际成交为准，不按当前价格或等级重算。
  • 部分数量成立时，只退对应数量。
  • 退款不改变原订单的交付事实，也不会让订单恢复为可取消。

举证要求

问题类型建议证据
账号类登录失败提示截图、尝试时间、是否使用正确的账号密码
卡密类兑换失败提示、兑换时间、是否已在他处使用
数量不足交付清单与订单数量对比
描述不符商品页与实际交付内容的差异说明

提高处理效率

工单描述包含「做了什么 → 看到什么 → 期待什么」三段，比只写「用不了」快得多。证据请用链接引用，不要上传含他人隐私的完整数据。

不适用情形

  • 消费者自身操作失误（输错账号、误删凭证）
  • 逾期未使用或已过有效期
  • 要求更换规格、退货退款以外的诉求
  • 未交付订单（应走取消）

错误

code / sub_code场景
PERMANENT / NOT_DELIVERED订单未交付，不能提交售后
PERMANENT / QTY_INVALID数量超过已交付量
PERMANENT / CASE_DUPLICATE同一订单行已有处理中的同类工单
PERMANENT / SCOPE_DENIED未开通 after_sales.write
