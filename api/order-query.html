查单 get_sales_order

约 528 字大约 2 分钟

按订单号或你的请求号查询订单状态，也可作为交付回调的补偿手段。

  • 权限：order.read
  • 幂等：只读
  • 建议频率：回调不可靠时按 5–30 秒退避轮询，不要高频扫

请求

两种方式二选一：

{
  "action": "get_sales_order",
  "schema_ver": "1.0",
  "req_id": "shop-a-20261124-q-001",
  "data": { "order_no": "XS20261124000123" }
}
{
  "action": "get_sales_order",
  "schema_ver": "1.0",
  "req_id": "shop-a-20261124-q-002",
  "data": { "ext_req_id": "shop-a-20261124-0001" }
}
字段类型必填说明
order_nostring二选一平台订单号
ext_req_idstring二选一你提交时的幂等键
with_deliverybool否是否返回交付摘要，默认 false

状态说明

字段值含义你可以做什么
accept_statereceived已收到，处理中等待
accepted已受理等待交付
rejected已拒绝不要重试，按原因修正
fulfill_statenone未交付等待或查询
full已整单交付领取交付物
fund_stateheld已冻结等待
captured已扣款已完成
released已释放订单取消或未成交
refunded已退款售后完成
after_sale_statenone / open / resolving / resolved售后进度按工单沟通

组合含义

正常完成是 accept_state=accepted + fulfill_state=full + fund_state=captured。若 fund_state=released，说明未成交并已解冻，不用再等货。

用于补偿

当接受订单时遇到超时或 UNKNOWN：

  1. 用 ext_req_id 查询。
  2. 有记录：按状态继续（已交付则领取，已拒绝则修正）。
  3. 无记录：等待 10–30 秒再查一次，仍无再用原键重试下单。

错误

code / sub_code场景
PERMANENT / ORDER_NOT_FOUND订单号不存在，或不属于当前店铺
PERMANENT / SCOPE_DENIED未开通 order.read
PERMANENT / PARAM_INVALID两个查询条件都未提供

不同店铺之间不能互查订单：同一账户下的 A 店查不到 B 店的订单号，这是隔离设计，不是数据丢失。
