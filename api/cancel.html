取消 req_cancel

约 464 字大约 2 分钟

对尚未交付的订单申请取消。取消是异步确认的，最终结果以查单或回调为准。

  • 权限：cancel.write
  • 幂等：按订单号，重复提交返回同一结果
  • 前置条件：订单未交付、未终结

请求

{
  "action": "req_cancel",
  "schema_ver": "1.0",
  "req_id": "shop-a-20261124-cxl-001",
  "data": {
    "order_no": "XS20261124000123",
    "reason": "消费者取消购买"
  }
}
字段类型必填说明
order_nostring是要取消的订单
reasonstring否取消原因，便于客服核对

响应

{
  "req_id": "shop-a-20261124-cxl-001",
  "corr_id": "c_7f3a97",
  "schema_ver": "1.0",
  "code": "OK",
  "message": "",
  "data": {
    "order_no": "XS20261124000123",
    "cancel_state": "requested",
    "requested_at": "2026-11-24T13:06:10Z"
  }
}
cancel_state含义后续
requested已受理，处理中等待回调或查单
done已取消冻结已释放
rejected不可取消见 reason_code

rejected 时 code 为 PERMANENT，sub_code 可能是 NOT_CANCELABLE（已交付）或 ALREADY_TERMINAL（订单已终结）。

规则

  • 未交付：可申请取消。确认取消后释放冻结，这是解冻，不是退款。
  • 已交付：不能取消。质量问题请走售后。
  • 处理中：取消是请求，不保证立即成功。若在取消确认前完成交付，订单仍会按交付处理，此时取消返回 NOT_CANCELABLE。
  • 已取消订单不可「复活」。需要重新购买时请用新的 ext_req_id 下单，并自行关联原单。

取消与退款的差别

动作触发条件资金表现
取消未交付冻结释放，可用余额恢复
退款已交付且售后核定按核定金额退回余额，新增退款流水

不要用取消来模拟退款，也不要在已扣款订单上反复提交取消。

错误

code / sub_code场景
PERMANENT / NOT_CANCELABLE已交付，无法取消
PERMANENT / ALREADY_TERMINAL订单已终结
PERMANENT / ORDER_NOT_FOUND订单不存在或不属于当前店铺
PERMANENT / SCOPE_DENIED未开通 cancel.write
CONFLICT同一订单重复取消且状态冲突
